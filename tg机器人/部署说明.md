# Telegram 发码机器人 · 零成本部署（Cloudflare Workers）

**总花费 0 元，不需要 VPN，不需要买服务器。**

原因：Cloudflare Workers 跑在 Cloudflare 自己的网络上，它的出口本来就不在中国大陆，所以它自己就能访问 `api.telegram.org`。是它去连 Telegram，不是你去连 —— 你只需要一个能打开 Cloudflare 后台的浏览器。

免费额度：每天 10 万次请求，一个发码机器人一天几十次都到不了。

---

## 部署步骤（大约 10 分钟）

### 1. 注册 Cloudflare
打开 `https://dash.cloudflare.com/sign-up`，用邮箱注册，验证邮件，免费账号即可，不用绑卡。

### 2. 建一个 Worker
左侧 **Workers & Pages** → **Create** → 选 **Worker** → 起个名字（比如 `efh-bot`）→ **Deploy**。
部署完会给你一个地址，形如：

```
https://efh-bot.你的用户名.workers.dev
```

### 3. 把代码贴进去
点 **Edit code**，把 `worker.js` 的全部内容覆盖进去 → **Deploy**。

### 4. 配环境变量（这一步最关键）
进 Worker 的 **Settings → Variables and Secrets**，加这几个：

| 名称 | 值 | 说明 |
|---|---|---|
| `BOT_TOKEN` | `123456:ABC...` | @taojia_group_bot 的 token（找 BotFather 拿） |
| `CODES` | `EFH-AAAA-BBBB-CCCC,EFH-DDDD-EEEE-FFFF` | 你手上的备用码，逗号分隔；不填就自动生成 |
| `ADMIN_IDS` | 你的 Telegram 数字 ID | 允许在群里发码的人；留空=谁都能在私聊领 |
| `DAILY_LIMIT` | `2` | 每人每天领几枚 |

`BOT_TOKEN` 一定要用 **Secret** 类型（不要用明文变量），避免在日志里露出。

### 5. 建 KV（记发码进度，可选但建议）
**Storage & Databases → KV** → Create namespace，名字随意 → 回到 Worker 的 **Settings → Bindings** → Add → KV namespace，**变量名必须填 `KV`** → 选刚建的那个 → 保存。

不建也能跑，只是重启后“今天领过几枚”的计数会丢。

### 6. 挂 webhook（一条网址搞定）
在浏览器打开：

```
https://efh-bot.你的用户名.workers.dev/?init=1
```

它会返回一段 JSON，里面 `"ok":true` 就成了 —— 这一步是 Worker 自己调用 Telegram 的 `setWebhook`，全程不需要你连 Telegram。

### 7. 试一下
在 Telegram 里给 @taojia_group_bot 发 `/test`，应该马上回一枚码。
群里发 `/test` 只有 `ADMIN_IDS` 里的人能领，其他人会被提示去私聊。

## 常见问题

**改了码池要重新部署吗？**
不用。改 `CODES` 后，KV 里的指针还在，会接着往下发；想从头发就把 KV 里的 `idx` 删掉。

**能发“兑换”而不是激活码吗？**
能，`CODES` 里塞什么就发什么，机器人不校验内容。

**会不会被人狂刷？**
私聊有 `DAILY_LIMIT`；群里只给管理员。真要防刷，把 `DAILY_LIMIT=1`，并在 `ADMIN_IDS` 里只写你自己。

**Cloudflare 后台打不开怎么办？**
国内偶尔慢，换手机流量或等一会儿再试。这一步不需要代理，打不开是网络抖动，不是被墙。
